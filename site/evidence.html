What we measured

Each comparison below used the same owned test package, inputs and task on every tool. The limits of each result are stated next to it.

Packages
Owned synthetic skills with known behavior: normal, active, dormant and approved variants.
Frozen in advance
Expected results and input bytes, recorded with SHA-256 before any scan.
Other tools
Local configurations only, grouped by category. No package was tuned against any tool.
Where
A development computer, 27 and 28 November 2026. Tesseract ran in its protected Linux runner.

Across 12 suite cases, Tesseract matched the expected output and behavior in all 12, with verified cleanup.

Same correct output, one extra side effect

Two versions of a text-audit skill returned identical, correct results. One of them also opened a planted SSH key decoy.

The second scanner’s vendor recommends a model-assisted mode for production. We did not test that mode. The decoy key was synthetic, and the record shows that the file was opened, not that it was read.

A new version does not inherit approval

Version 1.0.1 added one sentence to the skill’s documentation. Its output and receipt matched version 1.0.0 exactly. Its package fingerprint did not.

The review record is an unsigned local experiment. The protected runner does not require it yet.
