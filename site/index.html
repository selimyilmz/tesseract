PLATE 02 The Four Dimensions of Containment

Why We Call It Tesseract: The 4D Containment Lattice

In geometry, a tesseract is a 4-dimensional hypercube. In our architecture, containment spans four orthogonal enforcement and observation planes simultaneously — built without Docker or managed sandboxes.

Dimension X Pinned Wolfi Rootfs

Unshared Namespaces, Zero Host Root

We never bind-mount the host's / filesystem. Using bubblewrap with unshared user, mount, PID, IPC, UTS, and network namespaces, each job boots over a SHA-256 pinned, read-only Wolfi rootfs paired with kernel-bounded tmpfs mounts (nosuid,nodev,noexec). Host home folders and SSH keys never enter the cage; an external root fanotify sensor watches cage mounts and per-run decoy lures.

bwrap --ro-bind <pinned-wolfi-rootfs> / --unshare-user --disable-userns --cap-drop ALL --bind <bounded-tmpfs> /tmp --seccomp <fd>
Dimension Y Sealed Seccomp BPF

Default-Deny Syscall Filtering

A hand-built Berkeley Packet Filter (BPF) seccomp profile compiles via libseccomp into a kernel-sealed memfd and is verified against pinned BPF hashes before launch. Default action is EPERM (wrong architecture triggers SECCOMP_RET_KILL_PROCESS), blocking namespace creation, mounts, ptrace, bpf, keyctl, raw sockets, and O_NOATIME atime-check evasion.

default: EPERM (ACT_BADARCH: KILL_PROCESS) // sealed memfd + pinned BPF SHA-256
Dimension Z HTTP/HTTPS & IMDS Sinkhole

Zero-Egress Service Mediation

The cage runs in a loopback-only network namespace: direct internet sockets fail closed with ENETUNREACH. Proxy-aware HTTP and HTTPS (CONNECT TLS inspection, closed in N4) route via an in-cage bridge into a rootfs-isolated service unit that logs every request, scans payloads for per-run lures across raw and encoded forms, and never forwards upstream. Phase N6 adds in-cage cloud metadata (169.254.169.254) deception.

cage (netns lo) -> proxy bridge -> isolated service sinkhole (HTTP/HTTPS) -> 0 upstream egress
Dimension W Fail-Closed Evidence Chain

Root-Owned Hash-Chained Telemetry

Because the observer runs outside the worker's UID, untrusted code cannot tamper with its own log. Every event from the supervisor, fanotify file sensor, and sinkhole gateway links via prev_sha256 from a genesis run_id, enforces completeness latches so dropped telemetry never reports "clean", and is checked by an independent report reader.

event[n].prev_sha256 = sha256(canonical_json(event[n-1])) // root-owned store

PLATE 04 Engineering Rigor & Honesty

Claim Discipline: What We Prove vs. What Is Out of Scope

In security, overpromising is an immediate red flag. We separate what was observed in tests from what is enforced at runtime, and explicitly flag prototype status (security_accepted=false) until all remaining gates close.

What tesseract Enforces Today (1,265 WSL + 145 Root Tests)

Technically Enforced Guarantees

  • ■ Separate-UID Privilege Boundary: Untrusted code runs inside a transient DynamicUser service unit with isolated namespaces; the root supervisor, fanotify file sensor, and evidence store stay outside the worker's UID and mount view.
  • ■ Pinned Read-Only Wolfi Rootfs: Host / and personal folders are never mounted into the cage. Runtime trees and compiled seccomp BPF binaries are verified against pinned SHA-256 digests before launch.
  • ■ Default-Deny Seccomp (EPERM) & Cgroup v2: Sealed memfd BPF filters block forbidden syscalls (ptrace, bpf, keyctl, raw sockets, O_NOATIME); systemd cgroup v2 units cap CPU, memory, and tasks.
  • ■ Zero-Leftover Cleanup & Fail-Closed Evidence: Verified via the G025 20-job stress matrix, 10× deterministic repetition, and system-mode 0-leftover checks (7-job fingerprint unchanged); missing telemetry yields an incomplete verdict, never "clean".
Explicit Limitations (Prototype: security_accepted=false)

What We Do Not Claim

  • △ Host Kernel 0-Days & WSL2 Dev Boundary: Linux namespaces share the host kernel, and WSL2 is our development environment rather than a production security boundary. A disposable VM worker (M7) is required before testing unknown third-party packages.
  • △ Universal Safety Guarantee: Passing pre-install tests proves observed behavior on defined tasks and a pinned runtime — not an unconditional guarantee that a non-deterministic agent will behave identically on unseen inputs.
  • △ No Auto-Granted Permissions & Authorized Channels: Observed behavior never automatically grants runtime permissions. If an operator explicitly authorizes an upstream API, tesseract enforces the gateway boundary and scans for lures, but cannot judge arbitrary prompt semantics alone.
